# Requirements — subscription-closure (구독 마침표)

> 형식: EARS. ID는 코드·테스트·커밋 메시지에서 그대로 쓴다(`[Rxx]`).
> 범위: 오늘 MVP. "후속"으로 표시한 인수 기준은 이번 구현 범위 밖이며 완료로 보고하지 않는다.

## 소개
결제 전에 계속 쓸지 먼저 묻고, 해지·재가입 손익을 계산하고, 가족 동의를 모아 결제자에게 해지 경로를 넘기고, 해지 뒤 다음 청구까지 확인하는 로컬 우선 웹앱이다. 제품 런타임은 서버·로그인·LLM을 쓰지 않는다.

## 용어
- 결제자(owner): 원 서비스 청구 계정의 소유자. 실제 해지 권한을 가진다.
- H(horizon): 비교 기간(개월). k: 쉬는 개월 수(0 ≤ k ≤ H).
- 사건(case): 하나의 구독에 대한 검토→동의→인계→해지→다음 청구 확인의 묶음.

## 요구사항

### 입력·추출
- **R01 탐지** — WHEN 사용자가 결제 문자를 붙여넣으면 THE SYSTEM SHALL 기기 안에서 서비스·금액·결제일 후보와 원문 안의 근거 위치(start, end)를 만든다.
  - 인수: 합성 결제 문자에서 금액·서비스 후보와 span이 원문 부분 문자열과 일치한다. 광고·인증번호 문자는 결제 후보가 아니다.
- **R02 미확인 필드** — IF 금액·서비스·결제일이 근거에 없으면 THEN THE SYSTEM SHALL 그 필드를 `null`로 두고 사용자 확인을 요청한다.
  - 인수: 날짜 없는 문자에서 결제일을 추정해 채우지 않는다.
- **R03 중복** — WHEN 같은 입력을 다시 처리하면 THE SYSTEM SHALL 중복 구독·중복 알림을 만들지 않는다.
- **R04 사용량 미확인** — IF 사용량 관측 자료가 없으면 THEN THE SYSTEM SHALL 사용량을 "미확인"으로 표시하고 0회로 바꾸지 않는다.

### 결제 전 먼저 묻기
- **R05 검토 시점** — WHEN 확인된 다음 결제일까지 3일 이하가 남으면 THE SYSTEM SHALL 그 구독을 결제 전 검토함에 한 번 올리고 유지·쉬기 계산·가족 검토·해지 준비 중 하나를 고르게 한다.
  - 인수: 주입한 `now`로 D-3, D-1, 당일, 지난 기한을 구분한다. 결제일이 `null`이면 검토함 대신 "결제일 확인 필요".
- **R06 알림 한계** — WHILE 앱이 닫혀 있는 동안 THE SYSTEM SHALL 정시 알림을 보장한다고 표시하지 않고, `.ics` 일정(D-3·D-1 두 경고)을 대체 수단으로 제공한다.

### 가족 동의
- **R07 동의 전 잠금** — WHILE 가족 검토가 필요한 사건에 현재 버전의 필수 구성원 전원 동의가 없는 동안 THE SYSTEM SHALL 결제자 인계 상태로 전이하지 않는다.
- **R08 동의 무효화** — WHEN 제안 조건(H·k·가격·선택 대안·필수 요구)이 바뀌거나 구성원이 동의를 철회하면 THE SYSTEM SHALL 이전 버전의 응답을 무효화하고 재동의를 요청한다.
  - 인수: v1 동의를 v2에 제출하면 `stale_version`으로 거부된다.

### 해지 경로·사건
- **R09 경로 안내** — WHEN 서비스와 결제 채널이 확인되면 THE SYSTEM SHALL 출처·확인일이 있는 그 채널의 공식 해지 단계를 보여 준다.
- **R10 경로 불명** — IF 결제 채널을 모르거나 해당 채널 가이드가 없으면 THEN THE SYSTEM SHALL "결제 채널 확인 필요"로 보류하고 채널 확인 단계를 보여 준다.
- **R11 요청≠완료** — WHEN 해지 요청 기록만 있으면 THE SYSTEM SHALL 계약 종료로 표시하지 않는다. 해지 요청·사업자 확인·결제수단 상태·환불은 따로 기록한다.
- **R12 범위 한정 확인** — WHEN 다음 결제 예정일이 지나고 확인한 결제 경로에서 청구가 관측되지 않으면 THE SYSTEM SHALL "확인한 기간·경로에서 추가 청구 관측 없음"(`no_charge_observed_scoped`)만 표시한다. 예정일 전이거나 자료가 부족하면 보류한다.
  - 인수: 새 청구가 관측되면 같은 사건을 `reopened`로 되돌린다.

### 개인정보·실패
- **R13 원문 최소화** — WHILE 데이터를 저장하거나 내보내는 동안 THE SYSTEM SHALL 결제 문자 원문을 기본 제외하고 확인된 필드와 근거 위치만 남긴다.
- **R14 외부 경로 격리** — IF 개발 도구(MCP·훅)에 원문 경로·임의 파일 경로·추가 필드가 전달되면 THEN THE SYSTEM SHALL 거부하고 payload 없는 오류 코드만 기록한다.
- **R15 실패 보존** — IF 추출·저장·가이드 조회가 실패하면 THEN THE SYSTEM SHALL 미확인 상태를 보존하고 성공으로 바꾸지 않는다.
- **R16 단일 정책 관문** — WHEN UI나 도메인 명령이 상태 변경을 요청하면 THE SYSTEM SHALL 같은 `evaluateAction` 함수로 역할·동의·버전·상태를 검사한다.
- **R17 무로그인 재현** — WHEN 합성 데모 모드로 실행하면 THE SYSTEM SHALL Kiro·로그인·네트워크 모델 없이 핵심 흐름(손익→가족→인계→해지→재청구)을 재현한다.
- **R18 검증 기록** — WHEN 개발 검증 결과를 남기면 THE SYSTEM SHALL 요구사항 ID·소스 SHA·결과·실행 시각·수행 주체를 함께 기록한다.

### 재가입 손익 (필수 모듈)
- **R19 재가입 손익** — WHEN 기존 월가·신규 월가·비교 기간 H·쉬는 개월 k가 입력되면 THE SYSTEM SHALL 유지 총액(H×기존가), 쉬고 복귀 총액((H−k)×신규가), 부호 있는 손익(유지−쉬기), 손익이 0보다 커지는 최소 k를 계산한다.
  - 인수: 디즈니+ 스탠다드 9,900→11,500, H=12: k=1 −7,700, k=2 +3,800, k=3 +15,300, 손익분기 2개월. 프리미엄 13,900→16,500: k=1 −14,700, k=2 +1,800. 손익 0(동률)은 이득으로 세지 않는다. 정수가 아닌 값·음수·k>H는 거부한다.
- **R20 계산 전제 표시** — WHILE 손익 숫자나 조언 문장을 보여 주는 동안 THE SYSTEM SHALL 가격 출처·확인일·적용일·기존가 자격·H·k·가격 고정·쉬는 동안 0원·제외 비용 가정을 함께 보여 주고, 확인되지 않은 개인 입력이면 "예시 계산"으로 표시한다.
- **R21 대안 비교** — WHEN 사용자가 대안을 검토하면 THE SYSTEM SHALL 같은 H 동안 연간권·광고형·낮은 등급의 총액, 선납·환불 제약, 권리 차이(4K·광고·동시 시청), 기존가 상실을 표시하고, 사용자 필수 요구를 충족하지 못하는 대안은 "부적합"으로 순위에서 뺀다.
  - 인수: 연간권 115,000원 < 월 유지 118,800원(H=12, 3,800원 차). 광고형 7,000원×12=84,000원이지만 "광고 없음" 요구가 있으면 부적합.

### 마침표 봇 (Kiro 에이전트)
> 봇은 Kiro CLI 커스텀 에이전트(`.kiro/agents/machimpyo-bot.json`)다. 프로젝트 MCP 서버(`mcp/server.ts`)의 도구만 쓸 수 있고, 상태 변경은 앱과 같은 `evaluateAction`을 거친다.

- **R22 자율 점검** — WHEN 점검(patrol)이 시작되면(앱 버튼·예약 실행) THE BOT SHALL 가구 상태를 읽고, 새 결제 문자를 구조화하고, 3일 안에 결제될 구독을 찾고, 재가입 손익과 대안을 계산한 뒤, 열린 사건마다 다음 행동을 스스로 정해 MCP 도구로 실행한다.
  - 인수: 데모 가구에서 D-3 디즈니+를 찾아 손익(1개월 −7,700원·2개월 +3,800원)을 인용한 질문을 결제자에게 보낸다. 같은 질문이 이미 대기 중이면 다시 보내지 않는다.
- **R23 사람 결정 분리** — IF 유지·쉬기 선택, 가족 동의, 해지 요청, 사업자 확인처럼 사람이 정할 일이면 THEN THE BOT SHALL 알맞은 사람에게 계산 문장과 선택지를 보내고 기다린다. 봇이 사람 대신 투표하거나 해지를 기록하는 도구는 없다(`human_only`).
- **R24 거부 후 재계획** — WHEN 봇의 요청이 정책 관문에서 거부되면 THE BOT SHALL 거부 사유에 맞춰 계획을 바꾼다(미응답자 재요청, 반대 의견을 반영한 새 조건 계산·개정 제안). 같은 거부 행동을 그대로 반복하지 않는다.
- **R25 재청구 추적** — WHEN 해지 요청 뒤 청구 문자가 관측되면 THE BOT SHALL 사건을 다시 열고, 문자에서 확인한 결제 채널의 공식 경로를 결제자에게 안내한다.
- **R26 실행 영수증** — WHEN 봇 실행이 끝나면 THE SYSTEM SHALL 모델·걸린 시간·도구 호출·거부·보낸 메시지를 `docs/evidence/bot-runs/`에 남기고, 앱은 기록된 실행을 "녹화 기록"으로 표시한다.
- **R27 원문 비노출** — WHILE 봇이 결제 문자를 처리하는 동안 THE MCP SERVER SHALL 모델에 원문을 돌려주지 않고 구조화 필드와 근거 위치(start·end)만 돌려준다.
